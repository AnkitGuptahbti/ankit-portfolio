# Redis: The Complete Guide to In-Memory Data Store

Redis (Remote Dictionary Server) is an open-source, in-memory data structure store that has become one of the most popular tools in modern application development. Used by millions of developers worldwide, Redis serves as a database, cache, message broker, and queue. This comprehensive guide will explore everything you need to know about Redis, from basics to advanced patterns.

---

## What is Redis?

**Redis** is an in-memory key-value data store known for its blazing-fast performance, rich data structures, and versatile use cases. Created by Salvatore Sanfilippo in 2009, Redis has evolved into a powerful tool that goes far beyond simple caching.

### Key Features

- **In-Memory Storage:** Data stored in RAM for ultra-fast access
- **Rich Data Structures:** Strings, Lists, Sets, Hashes, Sorted Sets, and more
- **Persistence Options:** RDB snapshots and AOF (Append Only File)
- **High Availability:** Replication, Sentinel, and Cluster support
- **Atomic Operations:** All operations are atomic
- **Pub/Sub Messaging:** Built-in publish/subscribe messaging
- **Lua Scripting:** Execute complex operations atomically
- **TTL Support:** Automatic key expiration

## Redis Data Structures

### 1. Strings

The most basic Redis data type. Can store text, integers, or binary data up to 512MB.

```bash
# Set and get
SET user:1:name "John Doe"
GET user:1:name
# Output: "John Doe"

# Set with expiration (10 seconds)
SETEX session:abc123 10 "user_data"

# Increment (atomic operation)
SET views:post:1 0
INCR views:post:1
# Output: 1
INCRBY views:post:1 5
# Output: 6

# Multiple operations
MSET user:1:email "john@example.com" user:1:age "30"
MGET user:1:name user:1:email
# Output: 1) "John Doe" 2) "john@example.com"
```

**Node.js Example:**
```javascript
const redis = require('redis');
const client = redis.createClient();

await client.connect();

// Set string value
await client.set('user:1:name', 'John Doe');

// Get string value
const name = await client.get('user:1:name');
console.log(name); // "John Doe"

// Increment counter
await client.set('pageviews', '0');
await client.incr('pageviews');
const views = await client.get('pageviews');
console.log(views); // "1"
```

### 2. Hashes

Perfect for representing objects with multiple fields.

```bash
# Set hash fields
HSET user:1 name "John Doe" email "john@example.com" age 30

# Get single field
HGET user:1 name
# Output: "John Doe"

# Get all fields
HGETALL user:1
# Output: 1) "name" 2) "John Doe" 3) "email" 4) "john@example.com" 5) "age" 6) "30"

# Increment field
HINCRBY user:1 loginCount 1

# Check if field exists
HEXISTS user:1 email
# Output: 1
```

**Python Example:**
```python
import redis

r = redis.Redis(host='localhost', port=6379, decode_responses=True)

# Store user object
r.hset('user:2', mapping={
    'name': 'Jane Smith',
    'email': 'jane@example.com',
    'age': 28
})

# Get all fields
user = r.hgetall('user:2')
print(user)  # {'name': 'Jane Smith', 'email': 'jane@example.com', 'age': '28'}

# Get specific field
name = r.hget('user:2', 'name')
print(name)  # Jane Smith
```

### 3. Lists

Ordered collections of strings, perfect for queues and stacks.

```bash
# Push to list (left/right)
LPUSH tasks "task1"
RPUSH tasks "task2" "task3"

# Get list length
LLEN tasks
# Output: 3

# Get range
LRANGE tasks 0 -1
# Output: 1) "task1" 2) "task2" 3) "task3"

# Pop from list
LPOP tasks
# Output: "task1"

# Blocking pop (wait until element available)
BLPOP tasks 0
```

**Task Queue Example:**
```javascript
// Producer
async function addTask(task) {
  await client.rPush('task-queue', JSON.stringify(task));
}

// Consumer (worker)
async function processTask() {
  while (true) {
    const result = await client.blPop('task-queue', 0);
    if (result) {
      const task = JSON.parse(result.element);
      await handleTask(task);
    }
  }
}
```

### 4. Sets

Unordered collections of unique strings.

```bash
# Add members
SADD tags:post:1 "redis" "database" "caching"

# Check membership
SISMEMBER tags:post:1 "redis"
# Output: 1

# Get all members
SMEMBERS tags:post:1
# Output: 1) "redis" 2) "database" 3) "caching"

# Set operations
SADD tags:post:2 "redis" "nosql" "performance"
SINTER tags:post:1 tags:post:2  # Intersection
# Output: 1) "redis"
SUNION tags:post:1 tags:post:2  # Union
SDIFF tags:post:1 tags:post:2   # Difference
```

**Real-World Example (User Following):**
```python
# User 1 follows User 2 and User 3
r.sadd('user:1:following', '2', '3')

# User 2 follows User 3
r.sadd('user:2:following', '3')

# Who does User 1 follow?
following = r.smembers('user:1:following')
print(following)  # {'2', '3'}

# Mutual following
mutual = r.sinter('user:1:following', 'user:2:following')
print(mutual)  # {'3'}
```

### 5. Sorted Sets

Sets where each member has a score for ordering.

```bash
# Add members with scores
ZADD leaderboard 100 "player1" 200 "player2" 150 "player3"

# Get rank (0-based)
ZRANK leaderboard "player1"
# Output: 0

# Get top scores
ZREVRANGE leaderboard 0 2 WITHSCORES
# Output: 1) "player2" 2) "200" 3) "player3" 4) "150" 5) "player1" 6) "100"

# Increment score
ZINCRBY leaderboard 50 "player1"

# Get by score range
ZRANGEBYSCORE leaderboard 100 200
```

**Leaderboard Example:**
```javascript
// Add player score
async function updateScore(playerId, score) {
  await client.zAdd('leaderboard', { score, value: playerId });
}

// Get top 10 players
async function getTopPlayers() {
  const top = await client.zRangeWithScores('leaderboard', 0, 9, {
    REV: true
  });
  return top.map(({ value, score }) => ({ player: value, score }));
}

// Get player rank
async function getPlayerRank(playerId) {
  const rank = await client.zRevRank('leaderboard', playerId);
  return rank + 1; // Convert to 1-based
}
```

## Caching Strategies

### 1. Cache-Aside (Lazy Loading)

```javascript
async function getUser(userId) {
  // Try cache first
  const cached = await client.get(`user:${userId}`);
  if (cached) {
    return JSON.parse(cached);
  }
  
  // Cache miss - fetch from database
  const user = await db.users.findById(userId);
  
  // Store in cache (with 1 hour TTL)
  await client.setEx(
    `user:${userId}`,
    3600,
    JSON.stringify(user)
  );
  
  return user;
}
```

### 2. Write-Through Cache

```javascript
async function updateUser(userId, data) {
  // Update database
  const user = await db.users.update(userId, data);
  
  // Update cache immediately
  await client.setEx(
    `user:${userId}`,
    3600,
    JSON.stringify(user)
  );
  
  return user;
}
```

### 3. Write-Behind (Write-Back) Cache

```javascript
async function updateUserAsync(userId, data) {
  // Update cache immediately
  await client.setEx(
    `user:${userId}`,
    3600,
    JSON.stringify(data)
  );
  
  // Queue database update
  await client.rPush('db-updates', JSON.stringify({
    type: 'user-update',
    userId,
    data
  }));
  
  return data;
}

// Background worker processes queue
async function processDbUpdates() {
  while (true) {
    const update = await client.blPop('db-updates', 0);
    if (update) {
      const { type, userId, data } = JSON.parse(update.element);
      await db.users.update(userId, data);
    }
  }
}
```

### 2. Transactions

```javascript
// Using MULTI/EXEC
async function transferPoints(fromUser, toUser, points) {
  const multi = client.multi();
  
  multi.hIncrBy(`user:${fromUser}`, 'points', -points);
  multi.hIncrBy(`user:${toUser}`, 'points', points);
  
  const results = await multi.exec();
  return results;
}
```

### 3. Lua Scripts

```javascript
// Atomic rate limiting
const rateLimitScript = `
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local current = tonumber(redis.call('GET', key) or '0')

if current >= limit then
  return 0
else
  redis.call('INCR', key)
  if current == 0 then
    redis.call('EXPIRE', key, 60)
  end
  return 1
end
`;

async function checkRateLimit(userId, limit) {
  const allowed = await client.eval(rateLimitScript, {
    keys: [`ratelimit:${userId}`],
    arguments: [limit.toString()]
  });
  
  return allowed === 1;
}
```

## Real-World Use Cases

### 1. Session Management

```javascript
// Store session
async function createSession(userId, sessionData) {
  const sessionId = generateSessionId();
  
  await client.setEx(
    `session:${sessionId}`,
    3600, // 1 hour
    JSON.stringify({ userId, ...sessionData })
  );
  
  return sessionId;
}

// Get session
async function getSession(sessionId) {
  const data = await client.get(`session:${sessionId}`);
  return data ? JSON.parse(data) : null;
}
```

### 2. Real-Time Analytics

```javascript
// Track page views
async function trackPageView(pageId) {
  const today = new Date().toISOString().split('T')[0];
  const key = `pageviews:${pageId}:${today}`;
  
  await client.incr(key);
  await client.expire(key, 86400 * 30); // Keep for 30 days
}

// Track unique visitors
async function trackUniqueVisitor(pageId, userId) {
  const today = new Date().toISOString().split('T')[0];
  const key = `visitors:${pageId}:${today}`;
  
  await client.sAdd(key, userId);
  await client.expire(key, 86400 * 30);
}

// Get analytics
async function getPageAnalytics(pageId) {
  const today = new Date().toISOString().split('T')[0];
  
  const views = await client.get(`pageviews:${pageId}:${today}`) || 0;
  const uniqueVisitors = await client.sCard(`visitors:${pageId}:${today}`) || 0;
  
  return { views: parseInt(views), uniqueVisitors };
}
```

### 3. Rate Limiting

```javascript
async function rateLimit(userId, maxRequests, windowSeconds) {
  const key = `ratelimit:${userId}`;
  const current = await client.incr(key);
  
  if (current === 1) {
    await client.expire(key, windowSeconds);
  }
  
  if (current > maxRequests) {
    const ttl = await client.ttl(key);
    throw new Error(`Rate limit exceeded. Try again in ${ttl} seconds`);
  }
  
  return { allowed: true, remaining: maxRequests - current };
}
```

### 4. Distributed Locks

```javascript
async function acquireLock(resource, timeout = 10000) {
  const lockKey = `lock:${resource}`;
  const lockId = generateUniqueId();
  
  const acquired = await client.set(lockKey, lockId, {
    NX: true, // Only set if not exists
    PX: timeout // Expiry in milliseconds
  });
  
  return acquired ? lockId : null;
}

async function releaseLock(resource, lockId) {
  const lockKey = `lock:${resource}`;
  
  // Use Lua script to ensure we only delete our lock
  const script = `
    if redis.call("GET", KEYS[1]) == ARGV[1] then
      return redis.call("DEL", KEYS[1])
    else
      return 0
    end
  `;
  
  return await client.eval(script, {
    keys: [lockKey],
    arguments: [lockId]
  });
}
```

### 5. Job Queue Implementation

```javascript
class JobQueue {
  constructor(client, queueName) {
    this.client = client;
    this.queueName = queueName;
  }
  
  async addJob(jobData, priority = 0) {
    const job = {
      id: generateJobId(),
      data: jobData,
      createdAt: Date.now()
    };
    
    await this.client.zAdd(this.queueName, {
      score: priority,
      value: JSON.stringify(job)
    });
    
    return job.id;
  }
  
  async getNextJob() {
    const jobs = await this.client.zRange(this.queueName, 0, 0);
    
    if (jobs.length === 0) return null;
    
    const job = JSON.parse(jobs[0]);
    await this.client.zRem(this.queueName, jobs[0]);
    
    return job;
  }
  
  async processJobs(handler) {
    while (true) {
      const job = await this.getNextJob();
      
      if (job) {
        try {
          await handler(job.data);
        } catch (error) {
          console.error('Job failed:', error);
          // Optionally re-queue with lower priority
        }
      } else {
        await new Promise(resolve => setTimeout(resolve, 1000));
      }
    }
  }
}
```

## Persistence Strategies

### RDB (Redis Database Backup)

```bash
# redis.conf
save 900 1      # Save if 1 key changed in 900 seconds
save 300 10     # Save if 10 keys changed in 300 seconds
save 60 10000   # Save if 10000 keys changed in 60 seconds

dbfilename dump.rdb
dir /var/lib/redis
```

**Pros:** Fast restarts, compact file
**Cons:** Potential data loss (last snapshot to crash)

### AOF (Append Only File)

```bash
# redis.conf
appendonly yes
appendfilename "appendonly.aof"
appendfsync everysec  # always | everysec | no
```

**Pros:** Better durability, human-readable
**Cons:** Larger files, slower restarts

### Hybrid Approach

```bash
# Use both RDB and AOF
save 900 1
appendonly yes
aof-use-rdb-preamble yes  # Fast restarts with AOF durability
```

## Performance Optimization

### 1. Use Pipelining

```javascript
// Without pipelining (slow)
for (let i = 0; i < 1000; i++) {
  await client.set(`key${i}`, `value${i}`);
}

// With pipelining (fast)
const pipeline = client.multi();
for (let i = 0; i < 1000; i++) {
  pipeline.set(`key${i}`, `value${i}`);
}
await pipeline.exec();
```

### 2. Optimize Memory Usage

```bash
# Use hashes for small objects
HSET user:1 name "John" age 30  # Better than separate keys

# Set appropriate TTLs
SETEX temp:data 3600 "value"

# Use Redis memory analyzer
redis-cli --bigkeys
```

### 3. Connection Pooling

```javascript
const redis = require('redis');

// Create connection pool
const pool = redis.createClient({
  socket: {
    host: 'localhost',
    port: 6379
  },
  pool: {
    min: 2,
    max: 10
  }
});
```

## Best Practices

1. **Use Appropriate Data Structures**
   - Hashes for objects
   - Sets for unique collections
   - Sorted sets for rankings

2. **Set Expiration Times**
   - Always set TTL for cache entries
   - Use `SETEX` instead of `SET` + `EXPIRE`

3. **Key Naming Conventions**
   - Use colons for hierarchy: `user:123:profile`
   - Be consistent and descriptive

4. **Monitor Performance**
   ```bash
   redis-cli --latency
   redis-cli --stat
   redis-cli INFO
   ```

5. **Secure Your Redis**
   ```bash
   # redis.conf
   requirepass your_strong_password
   bind 127.0.0.1
   rename-command FLUSHDB ""
   rename-command FLUSHALL ""
   ```

6. **Handle Errors Gracefully**
   ```javascript
   try {
     await client.set('key', 'value');
   } catch (error) {
     console.error('Redis error:', error);
     // Fallback to database or return cached data
   }
   ```
